# 前端科普动画工具套件需求文档

> 版本：草案 v0.2（2026-09-30）
> 阶段：需求定义；尚未确定技术架构和实现排期

## 1. 背景与产品定位

本项目希望用前端技术提供一套制作数学、物理和计算机原理可视化内容的工具。创作者能以可复用的场景、图形、公式、动画和参数构建讲解内容；观众既能观看连续动画，也能暂停、逐步查看或调整参数。产物可以用于网页教学、科普文章、课堂演示和视频素材。

Manim 是**目标和概念参考**，不是兼容性目标。其官方文档以场景（Scene）、可见对象（Mobject）和动画（Animation）组织创作，并提供坐标图、公式和视频输出能力。本项目借鉴这些创作需求，优先发挥浏览器实时预览与交互的优势；不要求复刻 Manim 的 Python API、渲染结果或全部功能。[Manim 基础概念](https://docs.manim.community/en/stable/tutorials/building_blocks.html)、[示例库](https://docs.manim.community/en/stable/examples.html)、[输出说明](https://docs.manim.community/en/stable/tutorials/output_and_config.html)。

### 产品目标

1. 让开发者通过前端代码、非开发者通过可视化编辑器，制作可精确控制、可重复播放的二维讲解动画。
2. 让同一个内容既能按时间线播放，也能由观众调整参数并观察结果。
3. 提供数学、物理、计算机原理三类可直接运行、可修改的示例，降低首次创作成本。
4. 支持将作品嵌入网页，并导出可分享的静态图或视频素材。

### 首版产品形态（已确认）

首版同时交付 **JavaScript/TypeScript 编程式工具库** 和 **浏览器可视化编辑器**。两种创作方式使用同一套场景数据模型与预览、导出能力。可视化编辑器需独立完成基础作品，不要求用户先写代码；编程式工具库可以在普通前端项目中使用。云端项目管理和在线社区暂不计入首版。

共同支持的场景数据必须能在两种方式之间保存、打开和继续编辑。任意 JavaScript 函数或复杂自定义逻辑不承诺转换为可视化控件；遇到编辑器无法表达的可序列化扩展数据时，应明确标记为只读并在保存时保留。无法序列化的运行时代码应明确提示不能导入，不能声称已完成无损转换。

## 2. 用户与典型场景

| 用户 | 想完成的事 | 成功结果 |
| --- | --- | --- |
| 科普作者、教师 | 在可视化编辑器中用动态图和文字解释抽象概念 | 无需编程即可编辑对象与时间线，导出视频或嵌入课件网页 |
| 前端开发者 | 为文章或产品内教程制作交互图解 | 用组件或脚本接入现有页面，复用场景和样式 |
| 学生、自学者 | 观察参数变化并逐步理解过程 | 能暂停、拖动进度、修改参数，读到准确数值和单位 |

首批验收内容固定为三个跨领域示例：

- **数学：**正弦函数图像、运动点、切线与当前坐标；调整频率后图像和读数同步变化。
- **物理：**抛体运动轨迹、位置与速度向量；调整初速度或重力加速度后轨迹和读数同步变化，并标明理想模型的适用条件。
- **计算机：**二分查找的有序数组、左右边界、比较位置与步骤说明；可逐步执行并观察边界变化。

## 3. 范围与优先级

`P0` 是首个可交付版本必须满足的能力；`P1` 是基础可用后的增强；`P2` 是远期方向。首版以二维内容为核心。功能的具体 API 名称、渲染技术和 UI 框架留到技术设计阶段确定。

| 编号 | 优先级 | 需求与可验收行为 |
| --- | --- | --- |
| FR-01 | P0 | **场景定义。**当创作者通过代码或编辑器定义场景时，工具应允许设置画布尺寸、背景、时长和对象集合；同一项目可包含多个独立场景，并能单独预览指定场景。 |
| FR-02 | P0 | **二维对象。**当创作者添加线、箭头、圆、矩形、多边形、路径或图片时，工具应按指定位置、尺寸、描边、填充和透明度显示；对象应可分组、变换和删除。 |
| FR-03 | P0 | **文字与公式。**当创作者添加中英文文字或常用数学公式时，工具应显示清晰、可定位和着色的内容；公式语法错误应给出可定位的提示。首版只承诺文档列明的公式语法子集，不承诺完整 TeX 环境兼容。 |
| FR-04 | P0 | **坐标与图形。**当创作者设定坐标范围、刻度和函数或数据点时，工具应绘制带标注的二维坐标轴、曲线和点，并支持从数学坐标映射到画布坐标。超出定义域、非有限值和不连续点不得被错误连成一条线。 |
| FR-05 | P0 | **时间线动画。**当创作者通过代码或可视化轨道指定对象属性的起止值、起止时间和缓动方式时，工具应在指定时刻计算对象状态；至少支持出现/消失、移动、缩放、旋转、颜色或透明度变化，以及多个动画顺序或并行编排。 |
| FR-06 | P0 | **参数与状态联动。**当观众改变暴露的参数或播放时间变化时，依赖参数和逻辑时间的对象、公式、图表和数值读数应保持一致；非法或超出范围的输入应被拒绝或按明确规则纠正，并给出反馈。 |
| FR-07 | P0 | **预览控制。**当用户播放、暂停、重新开始、单步前进或拖动进度时，画面和数值读数应对应同一逻辑时刻；拖回已播放时刻后应得到相同状态，不依赖先前播放路径。 |
| FR-08 | P0 | **视图与层次。**当场景改变尺寸或嵌入容器大小变化时，坐标、对象顺序与文本布局应遵循声明的适配策略；创作者应能控制对象层级和可见区域，避免标注被意外裁切。 |
| FR-09 | P0 | **作品输出。**当创作者选择当前时刻时，应能导出对应静态图片；当选择一段时间线时，应能在支持的浏览器中导出可播放视频。应检测浏览器支持的格式并显示实际格式；若不支持视频录制，应提供逐帧图片导出的路径。两种创作方式导出的画面均不得缺少预览中的图形或公式。 |
| FR-10 | P0 | **网页接入。**当开发者在普通前端页面挂载作品时，应能设置容器、尺寸和初始参数，并在卸载时停止计时和释放事件监听；一个页面可同时挂载两个互不干扰的作品。 |
| FR-11 | P0 | **示例与文档。**当新用户打开项目说明时，应能分别按照编程式和可视化教程完成「创建场景 → 添加对象 → 添加动画 → 预览 → 导出/嵌入」；三个跨领域示例应可在两种方式中运行和修改共同支持的内容，并说明公式、模型假设、参数单位与关键 API。 |
| FR-12 | P0 | **错误反馈。**当场景配置、函数计算或资源加载失败时，代码与编辑器预览应展示可定位的错误信息；单个对象失败不应让页面无提示地空白，错误消除后应可继续预览。 |
| FR-13 | P0 | **编程式接口。**当开发者在 JavaScript/TypeScript 项目中引入工具库时，应能通过有类型定义的公开接口创建场景、对象、动画和参数，运行预览并获取可保存的场景数据；首版文档应提供最小可运行代码及各能力的输入约束。 |
| FR-14 | P0 | **可视化编辑器。**当创作者选择空白项目或模板时，应能在画布中添加、选中、移动和删除基础对象，使用属性面板编辑样式、文字、公式、坐标与参数，并通过受支持的表达式引用参数和逻辑时间；在时间线中应能添加/移动关键帧和调整时长。编辑器还应提供撤销/重做、即时预览、本地保存/打开和输出入口。上述操作不得要求编写代码。 |
| FR-15 | P0 | **双模式互通。**当作品使用共同支持的场景能力时，编辑器保存的项目应可由编程式工具库加载，代码生成的场景数据也应可在编辑器打开并继续修改；场景文件应包含格式版本并对无效数据给出错误提示。保存、重新打开后对象、时间线、参数与关键帧结果应一致。对编辑器无法表达的可序列化扩展数据，应只读展示且在再次保存时保留；无法序列化的运行时代码应明确提示不能导入。 |
| FR-16 | P1 | **创作提效。**增加布局约束、路径跟随、对象匹配变换、轨迹残影和可复用的动画组合；每项都应提供示例和独立参数。 |
| FR-17 | P1 | **分享与复现。**在本地文件保存之外，支持生成可复现的链接；重新打开后场景、参数与指定时刻应一致。是否提供托管服务另行决定。 |
| FR-18 | P2 | **高级场景。**在二维能力稳定后评估三维相机、光照、复杂公式匹配变换、音频轨与协作编辑，分别立项，不作为首版验收条件。 |

## 4. 端到端使用流程

1. 创作者选择编程式工具库或可视化编辑器，从空白场景或示例开始，设置画布比例和时长。
2. 通过代码或画布/属性面板添加图形、文字、公式、坐标轴与数据，定义关键帧或连续计算逻辑。
3. 暴露需要观众控制的参数，设置范围、默认值、单位和说明。
4. 在预览中播放、逐步检查、拖动进度，校验公式、读数与画面一致。
5. 保存可互通的场景文件，按需在另一种创作方式中继续修改，然后导出图片或视频，或把作品嵌入网页。

## 5. 非功能需求与质量门槛

| 编号 | 要求 | 验收方式 |
| --- | --- | --- |
| NFR-01 | **时间确定性。**画面状态由场景配置、参数和逻辑时间决定；暂停、跳转、变速及导出不得改变同一时刻的结果。 | 对三个示例分别比较顺序播放与直接跳转后的关键帧状态和读数。 |
| NFR-02 | **数学正确性。**示例的曲线、数值、单位和物理模型假设应有对应说明；不把数值近似表现为精确解。 | 对关键输入运行数值断言；检查边界值、无效值及模型说明。 |
| NFR-03 | **预览性能。**首版目标是在约定的桌面验收环境下，以 1280×720 画布和 100 个简单二维对象运行代表性场景时，播放平均帧率不低于 30 fps；验收设备、浏览器版本和测量方法在技术设计阶段固定。 | 使用统一样例测量连续播放 30 秒；记录帧率、内存增长及掉帧。 |
| NFR-04 | **兼容与降级。**预览应覆盖当前主流桌面浏览器的稳定版本；视频格式、编码和下载能力依浏览器实际支持检测，界面应清楚说明不可用功能及替代输出。 | 在约定的 Chrome/Edge、Firefox、Safari 版本验证播放、交互、图片输出和视频降级。 |
| NFR-05 | **可读与可操作。**播放控件、参数输入及编辑器核心操作可用键盘操作，具有可理解的标签与焦点状态；文字与背景应满足常见教学投屏场景的可读性。 | 键盘完成播放、暂停、进度、参数、对象选择和属性编辑；人工检查主要示例的文字与对比度。 |
| NFR-06 | **本地可用。**核心创作、预览和导出流程不依赖登录或远端渲染服务；示例所需资源应可随项目部署。 | 断开网络后运行本地构建产物，完成三个示例的预览及受支持的输出。 |
| NFR-07 | **安全边界。**若提供运行用户代码的在线编辑器，代码执行应被隔离，不能直接访问宿主页面敏感数据；该功能进入开发前须明确隔离与资源限制方案。 | 在编辑器交付前做跨域、死循环、资源耗尽和异常退出验证。 |

## 6. 首版完成标准

首版交付需要同时满足：

1. 所有 P0 功能与 NFR-01～NFR-06 的验收行为通过；不以单个演示视频代替工具能力。
2. 数学、物理、计算机三个示例均可在编程式和可视化方式中修改共同支持的内容、播放、暂停、跳转和输出；物理与数学示例通过独立数值校验。
3. 新用户可分别依据两条教程从零创建一个包含对象、公式或坐标图、动画和可调参数的场景；代码作品可在网页中挂载，编辑器作品可保存并由代码加载。
4. 共同支持的场景文件经过「编辑器 → 代码加载 → 编辑器」与「代码生成 → 编辑器修改 → 代码加载」两种往返验证后，关键帧结果和参数一致；不支持可视化编辑的扩展数据有明确提示且不丢失，运行时代码的导入限制有明确提示。
5. 项目明确列出首版公式语法、输出格式与浏览器支持范围；未支持的能力有清楚提示。

## 7. 暂不纳入首版

- 与 Manim Python 脚本或 API 兼容、直接转换现有 Manim 项目。
- 完整 LaTeX/Typst 工具链、服务端视频渲染和跨浏览器统一 MP4 编码。
- 三维渲染、音频剪辑、多人协作、账户系统、素材商城或内容社区。
- 自动保证所有创作内容的科学正确性；工具提供表达、校验示例和错误提示，内容结论仍由作者负责。

## 8. 待确认的产品决策

| 决策 | 当前建议 | 对后续设计的影响 |
| --- | --- | --- |
| 核心交付重心 | 浏览器交互与动画视频并重 | 若视频是唯一核心产物，需提前收紧编码格式、音频和输出质量要求。 |
| 首版场景维度 | 二维 | 若三维是必需项，渲染、相机和性能范围需重估。 |

确认上述决策后，再编写技术设计与开发任务拆解；本文件暂不指定具体渲染库或 UI 框架。
